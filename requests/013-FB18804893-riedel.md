## Descriptive Title

Ensure 3rd Party Web Engines apply same WebContentSettings.FilterPolicy as WebKit

## Request Type

Interoperability Request

## Feature Requested

WebContentSettings.FilterPolicy

## Reason for Request

My name is Frederik Riedel and I’m the developer behind an app called “one sec.” With one sec, we help millions of users around the world to save more than 1000+ years from scrolling social media every single week. We help grown-up adult users to limit their own screen time (not adolescents who are managed by their parents).

One important aspect of one sec is website blocking. For that, we make use of the WebContentSettings.FilterPolicy in the ManagedSettings framework (part of Screen Time). This is important:

* To block social media websites (e.g. during work hours).
* To completely block access to adult content sites (e.g. as part of our “Adult Content Detox” feature).

This works great, and users have a consistent experience on iOS: no matter if they’re using Safari, Chrome, Firefox, etc.

We are concerned that, now that under the DMA third party web engines are allowed, they will not follow the same consistent system-controlled WebContentSettings.FilterPolicy like WebKit, and thus blocked URLs become available through 3rd party web engines.

That’s why we ask Apple to ensure that:

* The system level WebContentSettings.FilterPolicy (curated from iOS settings and from 3rd party apps) becomes available to 3rd party web browsers as well.
* It is enforced (e.g. through review guidelines) that 3rd party web engines actually implement those FilterPolicies and don’t ignore them.

This should also affect apps that are not primarily web browsers but that also allow opening URLs in a Web View (such as Instagram). Right now they use WebKit, so restriction rules are enforced, but in the future they might switch to 3rd party browser engines as well.

## Product Description

one sec helps grown-up adult users limit their own screen time (not adolescents who are managed by their parents). Website blocking via WebContentSettings.FilterPolicy is important to block social media websites (e.g. during work hours) and to completely block access to adult content sites as part of our “Adult Content Detox” feature.

## How the Feature Will Be Used

one sec will use this feature to block access to certain user-configured websites (social media, online news, gambling, adult content, …) permanently or temporarily via WebContentSettings.FilterPolicy in all web browsers regardless of which browser engine is being used.

This should also affect apps that are not primarily web browsers but that also allow opening URLs in a Web View (such as Instagram). Right now they use WebKit, so restriction rules are enforced, but in the future they might switch to 3rd party browser engines as well.

## Where Offered

Worldwide

## Evaluation of Alternatives

Right now, we use WebContentSettings.FilterPolicy and it works great. This interoperability request is about the change introduced by the DMA which we find concerning: that 3rd party browser engines are now a possibility and might ignore system-level restrictions or not put the same care into implementing such APIs as WebKit/WKWebView.

Our current alternative is to tell users not to install 3rd party engines, because we cannot guarantee that our features will work with them.

##### August 11, 2025 — Apple to Developer

Thank you for your request. We are moving your request to Phase III (Development) of our interoperability process.

We will introduce new API to the BrowserEngineKit framework to interoperate with Web Content restrictions. In particular, the API will allow the client to check if Web Content restrictions are enabled and to add a particular URL to the allow-list so that it is no longer blocked by Web Content restrictions.

This is a mild engineering effort. We plan to complete development of this solution by March 2026, and ship it shortly thereafter. We will update you once we have shipped it in a beta release.

We believe this addresses your request. Please let us know within 5 working days if you have any feedback on the project plan. If we do not hear from you in that time frame, we will proceed with development work in accordance with the project plan described above.

##### August 25, 2025 — Apple to Developer

Thank you for your feedback. Adoption of BrowserEngineKit and its capabilities by browser developers is voluntary but necessary for developers seeking to use 3P browser engines in the EU. To provide effective interoperability, Apple’s solution will allow browsers running 3P engines the same ability to read Web Content restrictions that WebKit has today. However, it remains the responsibility of those browser developers to adopt and utilize such capability — or alternatively, to provide their own filtering or content restriction solution if they so choose.

We agree it is important for browsers to honor content restrictions set by users. Accordingly, we include those settings in WebKit such that they apply to all WebKit-based browsers. The European Commission has made clear, however, that we are unable to take this same approach when developers use 3P browser engines. To the extent you have concerns that browser developers may not implement these capabilities or honor such controls, we encourage you to raise these concerns with the Commission directly.
