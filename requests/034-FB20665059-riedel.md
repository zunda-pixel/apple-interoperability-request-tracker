## Descriptive Title

Request for On-Device Interoperability API: one sec × Structured Integration

## Request Type

Interoperability Request

## Feature Requested

HealthKit Data Sharing, Calendar Access, Reminders Access, App Groups

## Reason for Request

While our Structured / one sec integration already exists today and is actively used by thousands of users, it unfortunately depends on cloud-based data exchange to synchronize Structured’s local task data with one sec’s intervention logic.

This approach, however, goes directly against both our and Apple’s privacy principles:

* Even minimal data about a user’s tasks must currently leave the device to reach the other app.
* Users lose the certainty that the integration works fully offline, causing trouble during bad internet connections.
* Both developers must maintain backend infrastructure solely for this one-device use case.
* The integration becomes slower, more complex, and less reliable.

We would strongly prefer to perform all communication on-device, securely and privately — exactly as Apple encourages developers to do in so many other contexts (e.g., HealthKit).

Apple already provides powerful privacy-preserving data-sharing frameworks, such as:

* **HealthKit:** Allows apps to share user health data on-device with clear user consent.
* **Calendars and Reminders APIs:** Enable apps to access and contribute to personal scheduling data under strict system mediation.
* **App Groups:** Allow local data sharing between multiple apps by the same developer.

However, App Groups cannot currently be shared across multiple individual developers, which prevents responsible collaborations like ours from functioning in a truly private, local way.

We are therefore requesting Apple to extend this capability — under strong privacy and developer controls — so that independent apps can collaborate on-device without any server involvement.

## How the Feature Will Be Used

We propose an extension of App Groups that allows one developer to securely share a subset of local data with a trusted third-party app, after explicit user consent.

**Concept**

* App A (Structured) can authorize specific third-party apps (identified by bundle IDs, e.g. wtf.riedel.one-sec) to access a restricted App Group.
* App A can store a minimized, local task database or plist in this shared container — containing only essential task metadata such as titles and timestamps, but no sensitive or personal notes.
* App B (one sec) can read and write this shared data on-device, with user consent, to provide richer, context-aware experiences.
* All access is mediated by iOS, and revocable by the user at any time.

**Example flow**

1. The user enables the “Structured Integration” inside one sec.
2. iOS presents a native consent dialog: “Allow one sec to access data from Structured on this device?” [Allow] [Don’t Allow]
3. one sec can then locally read upcoming tasks and include them contextually in its interventions — for example, reminding the user: “You still have two tasks planned for today in Structured: ‘Finish report’ and ‘Call Anna.’ Would you really like to open Instagram right now?”

All of this happens entirely offline, on-device, and under strict user control.

**Privacy and security**

* User consent is explicit and revocable at any time.
* Optional developer control ensures only whitelisted apps can request access.
* On-device only: no (background) network access.
* Minimal data model: only lightweight, non-sensitive task metadata shared.

## Additional Information

We believe that this proposal perfectly aligns with Apple’s longstanding priorities:

* **Privacy by design:** All data stays on the user’s device.
* **User empowerment:** Transparent consent and control over which apps can interoperate.
* **Developer fairness:** Extends Apple’s internal interoperability capabilities (Calendar, Focus, HealthKit) to independent developers.

By enabling such on-device interoperability, Apple would set a gold standard for privacy-preserving, user-centric app collaboration on mobile platforms.

This capability would immediately make existing integrations like one sec × Structured faster, more private, and more reliable — and it would open the door for countless other meaningful, ethical, and innovative app partnerships in the future.

##### November 10, 2025 — Apple to Developer

We have reviewed your submission and determined that your request falls outside the scope of Article 6(7) DMA. Your request asks Apple to create new functionality on iOS or iPadOS (specifically, an on-device interoperability API to enable independent third party apps to share data) rather than make existing features available to your services or hardware. As noted in your request, App Groups facilitates data sharing only between multiple installed apps created by a single developer. Additionally, your request identifies other features — namely, HealthKit Data Sharing, Calendar Access, and Reminders Access — that rely on specific API frameworks that would not enable your requested functionality. For these reasons, we are not moving your request to the next phase of our interoperability process.

This concludes our review under Article 6(7) DMA.
