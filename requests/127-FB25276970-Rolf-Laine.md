## Descriptive Title

Allow a user-selected CarPlay navigation app to receive the vehicle’s voice-recognition (push-to-talk) button

## Request Type

Interoperability Request

## Feature Requested

CarPlay vehicle voice-recognition / push-to-talk button event (steering-wheel “Siri button”), currently reserved for Siri

## Reason for Request

In CarPlay, the vehicle’s dedicated voice-recognition button (normally on the steering wheel) is controlled by iOS and is available only to Siri. Apple’s CarPlay requirements for vehicle manufacturers state that “a hard button for Siri is required” and that the head unit must send iPhone all button up/down events (Developing CarPlay Systems, WWDC16). No public API lets a third-party CarPlay app receive this button event, even when the app is the active, foreground app on the CarPlay screen and even when the user would prefer it.

As a result, a driver who wants to give a voice command to the navigation app they are using (for example “add a fuel stop”, “avoid this road”, “how far to the destination”) must press the button, wait for Siri, say the app’s name, and then the request. Siri, an Apple service, has exclusive access to this hardware/software feature.

Under Article 6(7) of the Digital Markets Act, Apple must allow providers of services, free of charge, effective interoperability with the same hardware and software features accessed or controlled via iOS as are available to Apple’s own services. The voice-recognition button event delivered to iPhone through CarPlay is such a feature: it is controlled by iOS and currently used only by Siri. Article 6(3) DMA additionally requires that end users can easily change default settings on the operating system and virtual assistant that steer them to the gatekeeper’s own services; the push-to-talk button is effectively a default that always steers the driver to Siri.

We request that iOS (in the EU) let the user choose, in Settings and/or CarPlay settings, that the vehicle voice button activates a selected CarPlay navigation app’s voice function, at least while that app is the active navigation app in CarPlay, with Siri remaining the default for users who do not change the setting.

## Product Description

SuomiNavi+ is an iOS navigation app by Rolf Laine (Apple Developer Team ID K58D53H77S), developed in Finland and currently in TestFlight testing ahead of App Store release. It holds the CarPlay Navigation entitlement and provides turn-by-turn navigation in CarPlay. The app includes an in-app voice assistant (“Tekoäly”) that lets the driver plan routes and adjust navigation by voice.

## How the Feature Will Be Used

1. The user opts in: in iOS Settings / CarPlay settings, the user selects SuomiNavi+ as the app that handles the vehicle voice button (either always, or only while SuomiNavi+ is the active navigation app in CarPlay — both options are acceptable to us).
2. When the driver presses the steering-wheel voice button, iOS delivers the press (and button up/down events, as it does for Siri) to SuomiNavi+ instead of Siri, and grants the app the CarPlay voice audio session/microphone route that Siri uses.
3. SuomiNavi+ immediately shows the CarPlay voice control template, listens, and acts on the navigation request. No app name needs to be spoken.
4. A long-press or other gesture defined by Apple could still reach Siri, so Siri remains one action away. The app would use the button only for voice interaction, not for unrelated purposes.

Safety benefit: one press and one spoken sentence, eyes on the road and hands on the wheel. Today the driver must either look at and tap the CarPlay screen, or go through Siri and say the app name first, which takes longer and adds a failure point while driving.

## Where Offered

European Union

## Evaluation of Alternatives

* **App Intents / App Shortcuts (e.g. “Hey Siri, SuomiNavi”):** always routed through Siri. The driver must still invoke Siri and say the app name/phrase; the steering-wheel button itself still goes to Siri. This is the current workaround and is what this request seeks to make unnecessary.
* **SiriKit:** same limitation; Siri remains the entry point.
* **CarPlay framework (CPMapTemplate buttons, CPVoiceControlTemplate):** an on-screen voice button is possible, but it requires the driver to look at and touch the screen. It does not give access to the physical voice button.
* **MPRemoteCommandCenter / media buttons:** covers play/pause/next etc., not the voice-recognition button.
* **App Intents side-button assistant schema (AssistantIntent .activate, entitlement com.apple.developer.side-button-access.allow):** according to Apple’s documentation this is available only on iPhone in Japan (Japan-region Apple Account and physical presence in Japan), only for the iPhone side button, and not for the CarPlay vehicle voice button. It shows that Apple already has a technical design for a user-selected voice app; it is not available to us in the EU.

## Confidentiality

Fully available to other developers

## Additional Information

* **Precedent:** Since iOS 26.2 Apple lets users in Japan assign a voice-based conversational app to the iPhone side button instead of Siri. We ask for equivalent choice in the EU for the CarPlay voice button.
* iOS 26.4 allows voice-based conversational apps in CarPlay, but they still cannot be activated with the vehicle voice button; this confirms the button is the remaining exclusive Siri entry point.
* We are open to Apple-defined safeguards: user opt-in, CarPlay templates only, microphone use only while the voice UI is shown, and Siri still reachable.
